# Project Specification — OffboardAI MVP

## 1. Обзор проекта

**Название**: OffboardAI  
**Статус**: MVP  
**Целевой рынок**: B2B SaaS, knowledge management для инженерных команд  

**Краткое описание**: OffboardAI — сервис, который проводит 30-минутное структурированное голосовое интервью с уходящим инженером и за 24 часа генерирует Role Technical Passport — Markdown-документ с 7 разделами, содержащий архитектурные решения, скрытый техдолг, карту систем, регулярные ручные задачи, ключевые контакты и открытые вопросы. Документ предназначен для немедленного размещения в GitHub, GitLab или Notion.

**Миссия**: Превратить неструктурированные знания уходящего инженера в готовый к передаче технический актив, сохраняя его для команды до последнего дня сотрудника.

**Глобальная цель**: Стать стандартом де-факто для технического offboarding в engineering-командах 20–80 человек, сократив цикл восстановления контекста с 3–4 месяцев до 24 часов.

**Бизнес-модель**: Транзакционная — $1,500 за пилотный пакет (3 сессии), $500 за сессию после пилота. В перспективе — годовая подписка с неограниченными сессиями, API-интеграцией и корпоративным SSO.

## 2. Проблема и решение

### Ключевая боль пользователя

Когда senior-инженер покидает компанию, он уносит в голове критически важную информацию:
- **Архитектурные решения**: «Почему был выбран этот подход? Почему не использовали более простое решение?»
- **Скрытый техдолг**: «Это держится на честном слове» — места в коде, которые знает только один человек.
- **Регулярные ручные задачи**: «Какой скрипт запускать в конце месяца? Что делать вручную раз в неделю?»

**Последствия**: команда тратит 3–4 месяца на восстановление контекста. 84% топ-менеджеров обеспокоены потерей знаний, но только 8% компаний умеют их системно сохранять.

**Существующие альтернативы не решают проблему CTO**:
- **Sensay** → создаёт AI-чатбота, но не фиксирует техдолг и архитектурные решения
- **Notion/Confluence** → дают пустой шаблон, а не готовый документ
- **Loom** → часы видеозаписей, которые никто не пересматривает

### Решение

OffboardAI предлагает 4-шаговый консьерж-процесс:

| Шаг | Описание |
|---|---|
| **01** | **30-минутное Zoom-интервью** по специальному шаблону, нацеленному на системы, риски, решения и ручные процессы |
| **02** | **AI-транскрипция и DLP-фильтрация** — аудио транскрибируется, пароли/токены/API-ключи автоматически вырезаются |
| **03** | **Генерация Role Technical Passport** — GPT-4 структурирует знания в 7-секционный Markdown по корпоративному глоссарию |
| **04** | **Апрув инженером и передача CTO** — финальный документ готов для GitHub / GitLab / Notion |

**Ключевое позиционирование**: «Чатбот — это поиск. Паспорт — это документ, который живёт в вашем репозитории.»

## 3. Целевая аудитория

### Primary Persona: CTO (Chief Technology Officer)

- **Размер компании**: 20–80 инженеров
- **Контекст**: быстрорастущий tech-стартап или масштабирующийся product-стартап
- **Боль**: каждый уход senior-инженера оборачивается неделями восстановления контекста командой. Ключевой контекст уходит каждые несколько месяцев.
- **Триггер**: конкретное увольнение ключевого инженера с уведомлением 2 недели
- **Цена вопроса**: стоимость одного дня простоя команды из 5 инженеров > $2,500
- **Канал**: email (founders@offboard.ai)

### Secondary Persona: Engineering Manager (EM)

- **Контекст**: непосредственно управляет командой, из которой уходит инженер
- **Боль**: преемник роли получает репозитории без карты рисков, контактов и причин прошлых решений
- **Ответственность**: обеспечить continuity разработки после ухода ключевого участника

### Tertiary Persona: Уходящий инженер

- **Мотивация**: оставить команду в работоспособном состоянии, с чистой совестью передать дела
- **Время**: последние 2 недели — окно для интервью
- **Ограничение**: не должен тратить часы на заполнение документов вручную

## 4. Функциональные требования (MVP)

### Модуль 1: Управление сессиями (Session Management)

| ID | Требование | Приоритет | Описание |
|---|---|---|---|
| FR-01 | Создание сессии | P0 | CTO/EM создаёт сессию offboarding: указывает имя инженера, роль, email, срок ухода |
| FR-02 | Статус сессии | P0 | Сессия проходит через статусы: `created → interview_scheduled → interview_completed → passport_generating → passport_ready → approved → delivered` |
| FR-03 | Просмотр списка сессий | P0 | Дашборд со списком всех сессий, их статусами и ссылками на паспорта |
| FR-04 | Уведомления | P1 | Email-уведомления при смене статуса сессии (интервью назначено, паспорт готов) |

### Модуль 2: Интервью (Interview)

| ID | Требование | Приоритет | Описание |
|---|---|---|---|
| FR-05 | Генерация ссылки на Zoom | P0 | Система генерирует Zoom-ссылку для интервью (интеграция с Zoom API) |

## 7. Архитектурные рекомендации

### Технологический стек

| Компонент | Технология | Обоснование |
|---|---|---|
| **Frontend** | Next.js 16 + React 19 + TypeScript | Уже реализован лендинг, единый стек для app и dashboard |
| **Backend API** | Next.js API Routes | Serverless-функции в том же проекте (быстрый старт MVP) |
| **База данных** | PostgreSQL 16 | Реляционная модель с JSONB для гибкости секций паспорта |
| **ORM** | Prisma | Type-safe, миграции, отличная поддержка Postgres |
| **Аутентификация** | NextAuth.js / Auth.js | Google OAuth + Magic link, интеграция с Next.js |
| **Очередь задач** | BullMQ + Redis | Асинхронная обработка транскрипции, DLP, генерации |
| **AI** | OpenAI API (Whisper + GPT-4o) | Транскрипция + структурирование |
| **Интеграции** | GitHub App / GitLab API / Notion API | Экспорт паспорта |
| **Платежи** | Stripe | Оплата сессий |
| **Хостинг** | Vercel (frontend) + Railway / Render (worker) | Serverless для API, выделенный worker для AI |
| **Стороннее хранилище** | AWS S3 / R2 | Временное хранение аудио (удаляется после обработки) |
| **Мониторинг** | Sentry | Ошибки и производительность |

### Модель безопасности (Data Flow)

```
[Аудио] ──загрузка──► [S3 (временное, 60 мин TTL)]
                         │
                         ▼
              [Worker: Транскрипция]
                         │
                         ▼
              [In-memory: Raw Transcript]
                         │
                         ▼
              [Worker: DLP-фильтрация]
              ╔══════════════════════╗
              ║ regex: password/     ║
              ║        token/        ║
              ║        api_key/      ║
              ║        private_key   ║
              ╚══════════════════════╝
                         │
                         ▼
              [In-memory: Clean Transcript]
                         │
                         ▼
              [Worker: GPT-4 → Passport]
                         │
                         ▼
              [БД: Только Passport (Markdown)]
                         │
              [S3: Аудио удалено 🗑]
              [БД: Транскрипты удалены 🗑]
```

**Принцип**: Аудио и транскрипты существуют только во время обработки. Единственное, что сохраняется — финальный паспорт. DLP-фильтр запускается до сохранения любых данных.
